## 정상 · 권한 · 오류 상황별 결과

“기대 결과”는 테스트 코드의 단언(assert)이고, “실제 결과”는 위 실행에서 확인된 값입니다. 모든 항목이 기대와 같았습니다.

### 정상 처리

| 확인 항목 | 기대 결과 | 실제 결과 | 위치 |
| --- | --- | --- | --- |
| 계약 제안·수락 | 같은 `termsHash`로 수락하면 `Active` | 일치 | 컨트랙트 1·2, E2E 1·2 |
| 보고 → 검증 → 확정 | 매체·검증기관·광고주가 각각 다른 지갑으로 기록, 인정·보류 건수 저장 | 일치 | 컨트랙트 8, E2E 8~10 |
| 이의 제기 | 사유 해시 기록, 상태 `Disputed` | 일치 | 컨트랙트 9, E2E 13 |
| 판정: 발표 예시 5·3·2 | 매체 보고 5 → 인정 2, 제외 3 (미추천 2 + 추천 후 미표시 1) | 일치 | 단위 1 |
| 판정: 시연 4건 | 보고 4 → 인정 1, 보류 1 | 일치 | E2E 9 |
| 가시성은 보조 지표 | `AD_VIEWABLE`은 집계되지만 정산 건수에 영향 없음 | 일치 | 단위 6 |
| 재현성 | 입력 순서가 달라도 같은 데이터·정책이면 같은 결과 해시 / 정책이 다르면 다른 해시 | 일치 | 단위 18·19, E2E 11 |

## 개발 중 발견하고 고친 오류

테스트와 리허설 중 발견한 문제와 수정, 수정 후 확인 방법입니다. (AI 활용 과정의 상세는 [7-2. AI 활용 기록](07-ai-usage.md))

| 발견한 문제 | 원인 | 수정 | 확인 |
| --- | --- | --- | --- |
| 모의 시연에서 이전 데이터가 남아 광고주 등록부터 시작할 수 없고, 소비자 질문 기록이 어디에도 안 보임 | 켜 둔 개발 서버가 `.env` 변경 전의 예전 DB를 계속 읽음 | DB 클라이언트가 `DATABASE_URL` 변경을 따라가도록 수정(`lib/db.ts`), `npm run demo:reset`이 서버를 켠 채로 기록을 비우고 재배포, 소비자 화면에 ‘아직 보고되지 않은 기록 N건’ 안내 | E2E 14개 통과, 초기 화면 ‘첫 광고 상품 등록’ 확인 |
| 예전 주소(`/campaigns` 등)로 들어가면 404 | 역할별 화면으로 재구성하면서 경로 변경 | `next.config.ts` 리다이렉트 + 안내용 404 화면(`app/not-found.tsx`) | 개발 서버에서 직접 확인 |
| 이미 확정된 뒤 새 질문을 하면 다음 할 일이 보이지 않음 | 진행 단계 계산이 마지막 보고서만 봄 | 확정 후 새 기록이 있으면 ‘새 실적 N건 보고 · 광고 매체’로 다음 주기 시작 (`lib/client/progress.ts`) | E2E 12 (확정 후 새 기록 5건 보고) |
| `npm run ai:check`가 Windows에서 비정상 종료 | `process.exit` 호출 시 libuv assertion | 강제 종료 제거 | Claude 응답 5.1초, 광고 상품 추천 확인 |
| E2E 준비 단계에서 DB를 강제 초기화(`--force-reset`)하는 방식이 Prisma 안전장치에 막힘 | 테스트가 시연·개발 DB와 같은 파일을 지우고 다시 쓰는 구조 | E2E는 실행마다 새 DB 파일을 만들고, 별도 노드(8546)·서버(3100)·빌드 폴더 사용 | E2E 반복 실행 후에도 시연 DB 유지 |
| 깨끗한 클론에서 `npm run typecheck` 실패 | Next.js 라우트 타입이 개발 서버 실행 전에는 없음 | `next typegen && tsc --noEmit` | 아래 ‘새 환경 재현 확인’ |
| 화면 글자가 작아 발표장에서 읽기 어려움 (팀 피드백) | 기본 글자 크기 | 전 화면 글자 약 2px 확대, 홈을 실제 서비스형 대시보드로 재구성 | 단위·E2E 통과, 브라우저 확인 |

## 새 환경 재현 확인

평가자가 저장소를 처음 받는 상황을 흉내 내, **커밋 대상 파일만**(`git ls-files -co --exclude-standard`, 117개) 빈 폴더에 복사하고 `node_modules`·`.env`·DB·빌드 결과 없이 처음부터 실행했습니다. (2026-11-26, Windows 11, Node v24.15.0)

| 단계 | 명령 | 결과 |
| --- | --- | --- |
| 설치 | `npm ci` | 성공 (564개 패키지, 약 2분) |
| 환경 파일 | `.env.example` → `.env` 복사 | 성공 |
| 셋업 | `npm run setup` | 성공 (컨트랙트 컴파일, ABI 45개 항목 내보내기, `demo.db` 생성) |
| 단위 + 컨트랙트 | `npm test` | 19 + 20 통과 |
| 린트 | `npx eslint` | 오류 없음 |

이 과정에서 찾은 문제: 깨끗한 클론에서는 Next.js가 생성하는 라우트 타입(`RouteContext`, `LayoutProps`)이 아직 없어 `tsc --noEmit`이 실패했습니다.
개발 서버를 한 번이라도 띄우면 생성되기 때문에 기존 개발 환경에서는 드러나지 않던 문제입니다.
`typecheck` 스크립트를 `next typegen && tsc --noEmit`으로 바꿔, 같은 깨끗한 복사본에서 통과하는 것을 다시 확인했습니다.
