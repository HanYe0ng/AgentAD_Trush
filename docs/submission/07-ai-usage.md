## 2. 활용 원칙

1. **설계는 팀이, 구현은 AI와 함께.** MVP 구조(“시스템 아키텍처 v1.0”)와 집계 계약 정책(“광고 집계 계약 정책 v1.0”)은 팀이 작성한 문서를 AI에 입력으로 주고, 그 범위 안에서 구현을 요청했습니다.
2. **AI 결과는 실행과 테스트로 확인.** 매 단계 단위·컨트랙트·E2E 테스트를 돌리고, 통과 수치를 기록했습니다. 테스트가 늘어난 과정: 단위 14 → 19, 컨트랙트 16 → 20, E2E 8 → 11 → 14.
3. **사실은 코드로 다시 확인.** AI가 “된다”고 한 기능(예: Sepolia 배포, API 키 사용 방식)은 팀이 질문해 실제 코드·설정과 대조했습니다.
4. **되돌리기 어려운 작업은 팀이 직접.** Git 저장소 생성·커밋·푸시는 팀원이 직접 했습니다 (AI에는 방법 안내만 요청).
5. **서비스 안의 AI는 판정에 쓰지 않음.** 쇼핑 AI는 광고 기록을 *발생*시키는 역할만 하고, 집계·검증은 결정적인 규칙 엔진이 합니다.

## 5. 서비스 안의 AI — 쇼핑 AI

| 항목 | 내용 |

| 역할 | 소비자 질문에 맞는 상품을 후보 목록 안에서 최대 3개 추천. 광고 기록을 *발생*시키는 쪽이며 판정에는 쓰이지 않음 |

| 폴백 | 키·로그인이 없거나 호출이 실패하면 결정적인 규칙 기반 추천기로 자동 전환. E2E·리허설은 숫자를 고정하려고 `AI_PROVIDER=rule` 사용 |
| 확인 | `npm run ai:check` — Claude가 5.1초 만에 응답하고 광고 상품을 추천 (11/26) |
