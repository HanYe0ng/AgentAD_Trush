# 2. 작동하는 MVP — 이용 안내와 로컬 실행 절차

> 제출 항목 2 · “서비스 URL과 이용 안내 또는 로컬 실행 절차”
> 공개 배포 URL은 없습니다. 아래 절차로 평가자 PC에서 그대로 실행할 수 있고, 최종 발표에서는 같은 절차로 띄운 서비스를 현장 시연합니다.

## 한 줄 소개

**AgentAd Trust**는 AI 쇼핑 에이전트에 집행된 광고를 “AI가 받은 횟수”가 아니라 **“소비자 화면에 실제로 표시된 건”** 기준으로 다시 세고,
그 결과를 광고주·광고 매체·검증기관이 **각자의 지갑 서명으로 블록체인에 공동 확정**하는 웹 서비스입니다.

## 핵심 사용 흐름 (입력 → 처리 → 결과 확인)

```
광고주: 광고 등록·계약 제안 ─▶ 광고 매체: 같은 조건으로 수락 ─▶ 소비자: 쇼핑 AI에 질문
   (registerCampaign Tx)          (acceptCampaign Tx)            (수신·추천·표시 기록 생성)
                                                                          │
광고주: 최종 승인 ◀─ 검증기관: 원본 기록으로 다시 세고 등록 ◀─ 광고 매체: 실적 보고
 (approveReport Tx)         (verifyReport Tx)                     (submitReport Tx)
                                                                          │
                              블록체인 기록 화면: 5건의 승인 이력 · 권한 테스트 · 재현 확인
```

## 실행 환경

| 항목 | 요구 사항 |
| --- | --- |
| OS | Windows 10/11 (검증 완료), macOS·Linux도 동일 명령 (`.env` 복사 명령만 다름) |
| Node.js | 22 이상 (검증: v24.15.0) |
| Git | 저장소 복제용 |
| 브라우저 | Chrome·Edge 등 최신 브라우저. E2E 테스트는 Windows에 기본 설치된 Edge를 사용 |
| 네트워크 | 설치(`npm install`) 때만 필요. 실행은 로컬 블록체인이라 외부 네트워크·가스비·지갑 충전이 필요 없음 |
| AI 키 | **불필요.** 키가 없으면 규칙 기반 추천기가 응답 (Claude 사용은 아래 ‘선택’ 참고) |

## 로컬 실행 절차 (약 5분)

**① 저장소 복제와 설치**

```powershell
git clone https://github.com/HanYe0ng/AgentAD_Trush.git
```

```powershell
cd AgentAD_Trush
```

```powershell
npm install
```

**② 환경 파일 만들기** (macOS·Linux: `cp .env.example .env`)

```powershell
Copy-Item .env.example .env
```

**③ 컨트랙트 컴파일 + DB 스키마 생성**

```powershell
npm run setup
```

**④ 터미널 1 — 로컬 블록체인 노드 (켜 둔 채로 둡니다)**

```powershell
npm run chain
```

**⑤ 터미널 2 — 컨트랙트 배포 후 웹 서버 실행**

```powershell
npm run chain:deploy
```

```powershell
npm run dev
```

**⑥ 브라우저에서 http://localhost:3000 접속**

오른쪽 위에 초록색 **로컬 블록체인**, 서명 방식 **시연 지갑**이 보이면 준비 완료입니다.
(시연 지갑 = Hardhat 공개 테스트 계정 #1 광고주 · #2 광고 매체 · #3 검증기관. 실제 자산이 없는 공개 키이며 chainId 31337에서만 켜집니다.)

**(선택) 배포된 코드가 저장소 소스와 같은지 확인**

```powershell
npm run chain:verify
```

**(선택) 처음 상태로 되돌리기** — 시연 기록을 비우고 컨트랙트를 새로 배포합니다. 개발 서버는 켜 둔 채로 실행 후 새로고침.

```powershell
npm run demo:reset
```

**(선택) Claude로 쇼핑 AI 실행** — `.env`에 `ANTHROPIC_API_KEY`를 넣거나(또는 Anthropic CLI 로그인) `AI_PROVIDER=anthropic`. 확인 명령:

```powershell
npm run ai:check
```

## 이용 안내 — 역할별 화면

화면 왼쪽 메뉴가 역할입니다. 시연 지갑 모드에서는 각 화면에 맞는 역할 지갑이 자동으로 서명합니다. 홈의 **처리할 일 → 처리하기** 버튼을 누르면 다음 차례의 역할 화면으로 바로 이동합니다.

| 메뉴 | 사용자 | 할 수 있는 일 | 블록체인 기록 |
| --- | --- | --- | --- |
| 홈 · 광고 계약 현황 | 모두 | 핵심 지표, 역할별 처리할 일, 최근 블록체인 기록, 계약별 6단계 진행·정산 결과 | 조회 |
| 광고주 | 광고주 지갑 | 광고 상품 등록 + 계약 제안, 검증된 실적 최종 승인 또는 이의 제기 | `registerCampaign` · `approveReport` · `disputeReport` |
| 광고 매체 | 매체 지갑 (쇼핑 AI 운영사) | 계약 수락, ‘AI가 광고를 받은 횟수’로 실적 보고 | `acceptCampaign` · `submitReport` |
| 소비자 | 소비자 | 쇼핑 AI 채팅 (오른쪽은 발표용 시연 패널: 시연 조건·추천 질문·광고 기록) | 없음 (DB에 원본 이벤트 저장) |
| 검증기관 | 검증기관 지갑 | 기록을 한 건씩 대조, 증빙 지문 대조, 결과 등록·반려 | `verifyReport` |
| 블록체인 기록 | 누구나 | 블록 순서 승인 이력, 컨트랙트 권한 테스트, 검증 결과 재현 확인 | 조회 |

### 3분 따라 하기 (기대 결과 포함)

| 단계 | 화면 · 조작 | 기대 결과 |
| --- | --- | --- |
| 1 | **광고주** → 기본값 그대로 `등록하고 계약 제안하기` | “광고를 등록하고 계약을 블록체인에 제안했습니다” |
| 2 | **광고 매체** → `같은 조건으로 수락` | ‘확정된 계약’에 모아 데일리 텀블러 |
| 3 | **소비자** → 추천 질문 “3만 원 이하로 출근할 때 쓸 텀블러 추천해 줘” | ‘유료 광고 · 모아리빙’ 카드, 광고 기록 수신 ✓ 추천 ✓ 표시 ✓ |
| 4 | 추천 질문 “2만 원 이하 텀블러 추천해 줘” | 광고 카드 없음 (수신만, 예산 초과로 미추천) |
| 5 | 시연 조건 `화면 미표시` → 3번 질문 / `측정 오류` → 3번 질문 → 조건을 `정상`으로 복귀 | 미표시 보고 1건 / 표시 기록 없음 1건 |
| 6 | **광고 매체** → `실적 보고` | 보고 4건 (AI가 광고를 받은 횟수) |
| 7 | **검증기관** → `검증 실행` → `검증 결과 등록` | **4건 중 1건 인정 · 1건 보류**, 증빙 지문 일치 |
| 8 | **광고주** → `인정 실적 1건 최종 승인` | 홈 6단계 모두 완료, 정산 확정 1건 |
| 9 | **블록체인 기록** → 권한 테스트 `시도` 3개, `검증 결과 다시 계산해 비교` | 온체인 기록 5건, 3개 모두 **컨트랙트가 거부**, **재현 일치** |
| 10 | (선택) 소비자 `예시 대화 5건 만들기` → 매체 보고 → 검증기관 `증빙 변조해 보기` → `다시 검증` → `반려 기록` | 지문 **불일치** 탐지, 보고서 반려, 홈 ‘처리할 일’이 ‘실적 다시 보고’로 바뀜 |

화면별 캡처와 클릭 흐름은 [7-1. 설계](07-design.md#3-주요-화면과-클릭-흐름)에, 현장 시연 대본은 저장소의 [DEMO.md](../../DEMO.md)에 있습니다.

## 실제 구현과 모의 처리 범위

| 구분 | 실제로 동작하는 것 | 모의(시연용)로 처리한 것 |
| --- | --- | --- |
| 블록체인 | 로컬 Hardhat 노드(EVM, chainId 31337)에 실제 컨트랙트 배포·트랜잭션·이벤트·상태 변화. 권한 거부도 컨트랙트가 직접 revert | 공개 테스트넷(Sepolia) 배포는 스크립트·설정만 준비하고 실행하지 않음 |
| 지갑 서명 | 역할별 지갑이 각자 서명 (시연 지갑 자동 서명 또는 MetaMask) | 시연 지갑은 Hardhat 공개 테스트 계정을 브라우저에서 사용 (로컬 체인 전용) |
| 쇼핑 AI | Claude(`claude-opus-5-5`) 구조화 출력 또는 규칙 기반 추천기가 실제로 응답, 예산 조건은 서버에서 먼저 반영 | 상품 목록은 고정된 시연 카탈로그, 상품 사진 대신 카테고리 아이콘 |
| 광고 기록 | 수신·추천·표시·가시성·미표시 5종 이벤트를 실제 화면 동작(렌더링·IntersectionObserver)에서 기록, 표시 이벤트는 서버 발급 토큰(HMAC)이 있어야 저장 | ‘화면 미표시’, ‘측정 오류’는 시연 조건 버튼으로 연출한 장애 상황 |
| 검증 | 정책 엔진이 원본 이벤트로 판정(인정·제외·보류·중복), 증빙 해시·결과 해시 계산, 재계산으로 재현 확인 | 검증 엔진은 같은 서버에서 실행 (독립 기관 인프라는 아님) |
| 변조 탐지 | 보고 후 DB 원본이 바뀌면 다시 만든 증빙 지문이 체인 기록과 달라 탐지·반려 | 변조 자체는 시연 도구(`증빙 변조해 보기`)로 가짜 기록을 넣어 연출 |
| 정산 | 인정·보류 건수와 확정·이의 제기 상태를 체인에 기록 | 실제 광고비 결제·송금은 구현하지 않음 |
| 시연 데이터 | — | `예시 대화 5건 만들기` = 발표 예시(수신 5 · 추천 3 · 표시 2) 데이터 생성, 시연용 샌드박스 정책으로 계약 |

## 자주 생기는 문제

| 증상 | 해결 |
| --- | --- |
| 오른쪽 위 빨간 “블록체인 연결 필요” | 터미널 1에서 `npm run chain` → `npm run demo:reset` → 브라우저 새로고침 |
| `npm run chain`에서 `EADDRINUSE 8545` | 이미 노드가 켜져 있습니다. 그대로 쓰거나 기존 터미널을 종료 |
| 버튼을 눌렀는데 컨트랙트 오류 | 노드를 재시작해 체인 기록이 사라진 경우입니다. `npm run demo:reset` 후 새로고침 |
| 이전 리허설 데이터가 남아 있음 | `npm run demo:reset` 후 새로고침 (홈 ‘처리할 일’이 첫 광고 상품 등록부터 시작) |
| AI 답변이 느리거나 실패 | 자동으로 규칙 기반 추천으로 넘어갑니다. 고정하려면 `.env`에 `AI_PROVIDER=rule` |
